# 自用版桌面收纳逻辑（we.18）

普通栅栏是可移动的图标容器。桌面不再必须有一个收件栅栏。

- 从普通栅栏拖到桌面空白处，图标留在松手的位置；也可以拖回任意普通栅栏。
- 可以删除任意栅栏，包括旧版名为“桌面”的栅栏。普通栅栏删除后，里面的图标散放到桌面，真实文件的位置和内容不变。
- 桌面散放的位置会保存，重启或刷新后保留。多显示器断开时，散放图标暂时回到可用显示器。
- 手动放置优先于整理规则。“立即应用整理规则”也不会收回手动放在桌面的图标。
- 自动归类默认关闭；升级第一次也会关闭。重新打开后只处理新到达的桌面项目。
- 取消旧版定时重排已有项目的行为；闲置天数等时间条件仍可通过手动“立即应用整理规则”使用。
- “在桌面显示文件夹”仍是文件夹入口。拖入会操作真实文件；拖出到桌面会将文件实际移到桌面目录。删除入口只关闭窗口，文件继续留在原文件夹。

升级保留旧栅栏的名字、位置和内容，将旧“桌面”收件栅栏变成普通可删除栅栏。新安装只建立三个普通栅栏，不建立“桌面”收件栏。

散放图标使用透明桌面层，图标与空白处由同一个桌面视图接收输入。散放层不渲染液态玻璃，动态壁纸直接显示在它后面。运行期间 Explorer 原生图标统一隐藏，正常退出后恢复；watchdog 保留异常退出恢复机制。手动选择“恢复显示桌面图标”时会停用散放层，显示全部原生图标。

we.13 补齐了这一层的基础交互：

- 点击空白处或图标会获得键盘焦点。框选后可以直接复制、剪切、删除或打开；Ctrl 框选切换选择，Shift 框选追加选择。
- Ctrl+A、Esc、文件操作快捷键按整个散放桌面的选择处理；方向键按实际位置导航，支持输入名字定位、F2 重命名和 Alt+Enter 属性。
- 空白处右键菜单提供图标大小、排序、自动排列、网格对齐、刷新、粘贴、新建文件夹／文本文档／虚拟栅栏，以及系统显示和个性化设置。
- 自动排列默认关闭，网格对齐默认打开。菜单排序会重新排列散放图标；自动排列关闭时，后续刷新保留手动位置。
- 多选拖动保留相对位置，落到已占用的位置时整体寻找空位。组过大而无法放入目标显示器时，转为自动落位。
- 散放桌面新建和粘贴的文件留在桌面；新建文件夹自动进入重命名。复制、剪切使用 Windows Shell 文件数据对象，兼容资源管理器；删除和属性使用系统 Shell。
- 布局按桌面窗口的实际 DPI 换算，不再混用显示器枚举的缩放值。缩放变化后重新换算图标位置。

这仍是独立进程的自绘桌面。目前没有完整接入 Windows 的撤销／重做、第三方“新建”模板、触控／笔输入及读屏导航。真实文件操作进入 Windows 的撤销记录，但自绘桌面还没有调用该记录的入口。硬件多显示器、虚拟桌面切换和 Explorer 重启仍需持续验证，不能视为已经完全替代原生桌面。

we.14 调整了右键菜单：文件菜单先保留 Windows Shell 的命令及顺序，虚拟分组等软件命令收进 PecoFence 子菜单。菜单采用 Windows 11 风格的圆角、32 DIP 行距和深浅色，输入、键盘导航及子菜单仍由 USER32 管理。第三方扩展已有的自绘项目保留自己的绘制器；高对比度模式使用系统原样式。这是传统 HMENU 的样式调整，不是 Explorer 的新版短菜单，也没有注入 Explorer。

we.15 将普通文件右键改为短菜单：

- 顶部一排剪切、复制、重命名和删除；下面保留打开、打开方式、属性、PecoFence 子菜单和“显示更多选项”。多选时禁用重命名。普通文件打开短菜单时不加载 Shell 扩展。
- “显示更多选项”、Shift+F10 或 Shift+右键打开完整 Windows Shell 菜单，保留系统命令顺序和第三方扩展。回收站等系统项目继续直接使用 Shell 菜单。
- 顶部按钮支持鼠标及左右方向键、Enter。高对比度模式将这些操作显示为普通系统菜单项目。短菜单仍由本程序呈现，没有调用 Explorer 的私有菜单宿主。
- 散放桌面取消窗口圆角和可调整大小的边框；拖入桌面空白处不再整面染色，拖放提示显示“桌面”。
- 从散放图标或文字开始拖动会保留实际抓取位置；网格吸附和碰撞避让仍按桌面设置工作。Ctrl+桌面拖动复制真实文件，Alt+桌面拖动创建快捷方式；原项目的位置和内容保留。
- 桌面排序先显示系统项目，再显示文件夹和文件，同类项目按所选排序方式排列；名称排序按数字自然顺序处理，例如 Document2 在 Document10 前面。

CLI 可使用 `item list --fence desktop` 查看散放图标，`item move <项目> --to desktop` 将项目移出普通栅栏，`item move <项目> --to <栅栏>` 放回容器。散放项的 `fence` 为全零 UUID，`fenceTitle` 为“桌面散放”；它不出现在 `fence list` 中。

we.17 继续打磨桌面交互：

- 桌面采用独立的 `PecoFence.Desktop` 窗口类型，普通栅栏的标题合并、吸附对象、避让和拖放描边不再把整张桌面当作一个栅栏。桌面全屏覆盖工作区也不会被误判为需要暂停玻璃的全屏应用。
- 桌面多选拖动保留所有可见图标的原始排列；不再因为超过四个图标或超过 320 DIP 的预览范围就收成一叠缩略图。预览仍限制单边不超过 4096 物理像素，只在开始拖动时生成。
- 点击其他栅栏、桌面空白或其他应用会取消普通栅栏内的选中状态。自身右键菜单、重命名输入和正在进行的 OLE 拖动保留当前操作所需的选中项。
- 桌面点击明确取得前台与键盘焦点，让 Windows 开始菜单能够正常收起。
- 普通栅栏拖动受显示器工作区约束，任务栏占用区域不再是可落位区域；关闭吸附或按 Alt 临时关闭吸附时仍受约束。单个栅栏与组拖动共用这项约束，尺寸超过工作区的窗口保留尺寸并将标题置于可见区域。
- 菜单字体为 13 DIP，普通行高 28 DIP，工具栏 38 DIP，分隔行 7 DIP；宽度按内容计算且至多 280 DIP，高度至多 300 DIP 且不超过点击位置所在显示器工作区高度的 70%。超长菜单由 USER32 提供滚动，完整 Shell 菜单保留第三方自绘项目。
- 弹出菜单时释放应用状态借用，让壁纸、动画、焦点与 CLI 消息继续处理。选择菜单命令后再应用结果，避免整个弹出期间冻结动态玻璃。


we.18 调整图标资源与交互收尾：

- 图标请求包含提取模式和唯一请求编号；刷新、样式变化后，已作废的排队任务跳过 Shell 提取，迟到结果不再写回缓存或结束新请求。
- 保留两个 STA 图标工作线程。可见图标优先于预取；只准备当前视口及附近最多 48 项的图标和文本，远处项释放图标引用。
- CPU 图标缓存采用 LRU，预算 512 项 / 16 MiB；GPU keyed bitmap 缓存预算 1024 项 / 64 MiB，壁纸纹理继续使用原有独立缓存。单张超过字节预算的资源允许单独保留，避免超大裁图每帧重新上传；预算针对缓存持有的资源，正在显示的引用不会被强制销毁。
- 鼠标捕获丢失、WM_CANCELMODE、外部失活和 Escape 使用同一取消路径，恢复栅栏位置和标签顺序，清除合并提示，避免将半次拖动当作提交。正常松手仍将最后的指针位置提交一次。
- 释放鼠标捕获前检查所有者，避免取消旧会话时释放新窗口已取得的捕获。自身菜单继续保留当前选择和动态效果。
